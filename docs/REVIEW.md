# Lotto Lab v2 구현 검토 기록

## 기존 저장소 분석

- 기준 커밋: `6a0ac6f` (`origin/main`). 작업 브랜치: `feat/lotto-lab-v2`.
- 프레임워크·패키지·빌드 도구가 없는 단일 `index.html` 정적 앱. CSS, DOM 처리, 통계, 생성 로직이 한 파일 안에 존재했다.
- 데이터는 `data/all.json`, `data/recent.json`, 외부 공개 JSON, HTML 내장 기록 순으로 시도했다. 배열 여부만 확인하여 데이터 정확성·회차 중복·갱신 지연 검증이 부족했다.
- 조사 시 `all.json`은 1~1,246회 (최신 2026-10-17), `recent.json`은 1,201~1,243회 (43개, 최신 2026-09-26). 회차 레코드는 `draw_no`, `numbers[6]`, `bonus_no`, `date`; 전체 데이터에는 `divisions`의 등수별 당첨금도 있다.
- `.github/workflows/update-lotto.yml`: 주간 스케줄 `30 15 * * 6`, 수동 실행 가능. `smok95.github.io/lotto/results/all.json`을 받아 `all.json`만 커밋한다. 이 작업에서는 workflow와 데이터 두 파일을 수정하지 않았다.
- 별도 Pages 배포 workflow는 없다. 기존 README는 main/root 배포를 안내한다. GitHub의 실제 Pages 관리 설정은 이 작업에서 조회·수정하지 않았다.
- 기존 기능: 최근 회차, 고빈도·최근성 기반 제외 추천, 수동 제외, 합계·홀짝·3배수·소수·저번호·연번 필터, 랜덤 생성. 생성 상한은 20,000회 시도, 시드·Worker·저장 기능이 없었다. 실제 점수식은 `100 - abs(sum - 140)`였다.

## 재사용·구조 선택

기존 데이터 스키마, 당첨 기록, 자동 갱신 workflow, 정적 호스팅, 번호 지표의 수학적 정의, 고빈도·최근성 제외 추천 방식과 사용자 흐름을 유지했다. 추천 기준은 설명 가능한 정렬로 단순화했다. HTML 내부의 기록 복제본은 제거하고 검증한 같은 출처 파일과 마지막 정상 캐시를 사용한다.

React로 전환하는 대신 브라우저 ES 모듈로 분리했다. 기존 main/root Pages와 데이터 갱신만으로 계속 동작할 수 있고, Vite는 개발·프로덕션 번들 생성용이다. 외부 폰트·CDN·AI API에 런타임 의존하지 않는다. `/lotto/`에 고정된 Vite base와 상대 경로 데이터 로딩으로 GitHub 프로젝트 Pages 경로를 지원한다.

## 구현과 알고리즘

1. 후보: 문자열 시드를 FNV-1a로 해시하고 Mulberry32로 난수를 생성한다 (비암호학적). 가능한 조합 순번을 sparse Fisher–Yates로 중복 없이 뽑고 사전순 조합 unranking으로 번호 6개로 변환한다. 거절 재추출이 없어 작은 풀에서도 무한 재시도하지 않는다.
2. 요청량: 100~100,000은 **필터 적용 전 고유 후보 수**다. 가능한 조합 수보다 많으면 그 수로 제한하고 안내한다. 제외수 39개라면 후보 1개만 검사한다.
3. 필터: 활성화한 모든 조건의 AND. 범위는 양 끝 포함. 홀짝은 선택한 홀수 개수 중 하나를 허용한다. 소수는 2~43 중 소수 집합, 합성수는 1보다 크며 소수가 아닌 수. 연번은 정렬된 인접 차이 1인 쌍 수 (1·2·3이면 2쌍). 번호대는 1~10/11~20/21~30/31~40/41~45.
4. 점수: `near(x,t,s) = max(0, 1 - abs(x-t)/s)`. 합계 `(145,100)`, 홀수 `(3,3)`, 3배수 `(2,4)`, 소수 `(2,4)`, 연번 `(1,4)`의 target/scale을 적용한다. 최근 3/10회 유사도는 각 회차의 합계(scale 100), 홀수(scale 6), 소수(scale 6) 거리 유사도를 평균한다. 가중치 기본 20/20/15/15/10/10/10, 사용자 가중치 합으로 나누어 총 100점으로 정규화한다. 필터와 독립적이다.
5. TOP: 점수 내림차순, 동점은 번호 사전순. 랜덤은 통과 후보에 부여한 독립 PRNG 우선순위 순서. 혼합은 점수 `ceil(TOP/2)`개와 랜덤 나머지, 중복 제거. 중복도 제한은 선택된 모든 조합과 번호 교집합 크기를 검사하는 탐욕적 방식이며 최적해 보장은 없다. 제한 때문에 TOP이 부족할 수 있음을 표시한다.
6. 비교: 통과 후보 랜덤과 **1~45 전체 무필터 랜덤**을 별도로 표시한다. 후자는 제외수·필터·다양성 제한을 적용하지 않는 독립 시드의 비교군으로, 점수는 참고용으로만 계산한다.
7. Worker: 500개 단위 진행 알림과 이벤트 루프 양보로 취소 요청을 처리한다. 취소 시 현재까지의 부분 결과와 상태를 구분한다. 전체 통과 후보 CSV를 Worker에서 생성해 전달하여 메인 스레드에서 100,000개 상세 객체를 복제하지 않는다.
8. 저장: localStorage에 설정 최대 30개, TOP·실행 설정 최근 10개, 구매 후보를 보관한다. 전체 후보는 실행 직후 CSV 다운로드로 보관하며 기록에는 넣지 않는다. 저장 공간 부족 시 오류를 안내한다. 설정 JSON은 버전·필터·가중치·제외수·실행 범위를 검증하고 가져온다.
9. 데이터: 모든 회차의 번호·보너스·유일성·날짜 검증. 로컬 파일과 캐시 중 최신 회차를 선택한다. 다음 주 추첨 시각 20:35 KST + 2시간 이후에도 이전 회차라면 갱신 지연을 표시한다. 파일 갱신 시각과 요청 확인 시각은 구분한다. 공개 데이터셋을 제3자 출처로 표시하며 공식 동행복권 대조가 필요함을 안내한다.
10. 확장: `statisticalProvider.recommend(history, options)` 인터페이스로 추천을 교체할 수 있다. `prepareBacktest`는 목표 회차 **이전** 기록만 추천에 전달하고, 엔진도 그 기록만 받도록 설계했다. 정답은 `evaluateBacktest`에서만 비교한다. 1~5등과 데이터에 있는 실제 당첨금을 판정하며, 없는 금액을 임의 추정하지 않는다.

조건부 1등 확률 유틸리티는 **당첨번호 6개가 남았다는 조건 아래** `서로 다른 구매 줄 수 / C(남은 번호 수,6)`이다 (최대 1). 실제 무조건 1등 확률이나 필터 효과의 실증값과 혼동하지 않는다. 일반 1줄의 1등 확률은 1/8,145,060이다.

## 검증 결과

2026-10-25 KST, Node 24.19.0, Vite 7.3.7, 시스템 Chromium에서 확인했다.

- `npm test`: **15/15 통과**. 모든 범위 필터의 경계·비활성화·홀짝, 수학 지표, 점수 합산·정규화, 100,000개 유일성·제외수·시드 재현, 생성 용량, 취소, TOP 모드·중복도, 1~5등/보너스, 조건부 확률, 미래 기록 격리, 데이터 캐시 폴백, 설정·CSV·저장 오류 검증.
- `npm run build`: **통과**. 앱 JS 약 24KB / gzip 9.3KB, CSS 약 11.7KB / gzip 3.2KB, Worker 약 6.4KB. `dist/data/`에 원본 데이터 복사.
- `npm run test:e2e`: **4/4 통과**. `/lotto/`에서 실제 Worker·JSON fetch를 포함한 빌드 실행, 모바일 선택 → 추천 부분 채택 → 프리셋 → 생성 → TOP → 구매 후보 → CSV/JSON 다운로드 → 재실행 재현 → 새로고침 후 복원. 로컬 저장소 접근 자체가 차단되어도 데이터 로딩·시뮬레이션이 동작하고 저장 실패 안내를 표시하는 예외 경로도 통과했다.
- 100,000개 후보 필터 비활성 실행: 약 **1.28초** (엔진 측정, 현재 클라우드 머신). 화면 20ms 타이머 **93회**, 최대 간격 **33ms** 관측. 취소 후 부분 결과와 재실행 가능 상태 확인. 실제 휴대폰 CPU·메모리 성능 보장은 아니며 별도 실기기 측정은 하지 않았다.
- 320 / 360 / 390 / 768 / 1280px viewport 가로 넘침 없음. 390px 모바일과 1280px 데스크톱 캡처를 육안 확인. 라이트·다크 전환, 범위 입력 오류 표시 확인.

## 남은 작업

- 백테스트 회차 선택 실행 UI, 다회차 성과 집계, 사후 조건부 실험 모드. 현재는 사전 데이터 격리/평가 모듈과 테스트만 제공하며 사후 실험 성과를 예측 성과로 표시하지 않는다.
- 통계 분포에서 자동 생성하는 추천 필터 프리셋. 현재 사용자 프리셋과 기본 필터를 제공한다.
- 생성형 AI API 및 인증·호출 제한·비용 제한 서버. 프런트엔드 API 키 없음.
- IndexedDB, 계정·클라우드 동기화, 실행 전체 후보의 브라우저 장기 저장.
- 실기기 성능·스크린리더·장시간 실험·대규모 저장 스트레스 검증.
- 운영 데이터 자동 갱신의 스키마 검증·원자적 교체·`recent.json` 동시 갱신 개선. 기존 운영 흐름을 이번 MVP에서 변경하지 않았다.
- main 병합, 원격 push, PR 생성, Pages 배포 및 공개는 **수행하지 않았으며 별도 승인 이후** 진행한다.
